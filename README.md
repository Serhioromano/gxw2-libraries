# Coolmay GX Works 2 Libraries

Библиотеки Structured Text (ST) для ПЛК **Mitsubishi FX / Coolmay FX3G** в среде **GX Works 2** (FX3U, FX3G, FX3S, FX5U).

Репозиторий содержит готовые переиспользуемые библиотеки: документацию для конечного пользователя, скомпилированные файлы `.sul` для установки в GX Works 2, исходные тексты (где есть) и проект-компилятор `compiler.gxw`, в котором все библиотеки собираются вместе и проверяются на ошибки.

| ---------- | ---------- | ------------ | ------------------------- |
| **AlarmManager** | Управление авариями и событиями: регистрация, фильтрация по процессу и важности, защёлкивание, задержка срабатывания, управление зуммером, упаковка состояний для HMI | `libraries/AlarmManager/AlarmManager.md` | TimeControl |
| **Utils** | Полезные функции и функциональные блоки общего назначения | `libraries/Utils/Utils.md` | — |

| **ModbusDriver** | Драйвер Modbus RTU (master / slave) для портов 2 и 3 | `libraries/ModbusDriver/Modbus.EN.md` и `Modbus.RU.md` | Utils, TimeControl (ticker 50 мс) |

### AlarmManager

Полнофункциональная система аварий и событий. Хранилище аварий (`AM_ALARMS`, `AM_EVENTS`) и константы ёмкости (`c_AM_ALARMS_NUM`, `c_AM_EVENTS_NUM`) объявляет **само приложение** в глобальных метках проекта — библиотека не резервирует память за вас, размер хранилища подстраивается под задачу.

Основные блоки: `FB_AM_INIT` (настройка свойств аварии), `FB_AM_SET` (регистрация условия), `FB_AM_ORISON`, `FB_AM_HAS_ALARMS`, `FB_AM_IS_BLOCK`, `FB_AM_BUZZER` (зуммер), `FB_AM_RESET`, `FB_AM_EV` / `FB_AM_EVENT_RESET` (события), `FB_AM_PACK_ALARMS` / `FB_AM_PACK_EVENTS` (упаковка состояний в регистры `D`/`R` или в биты `M` для HMI), `F_AM_DELAY_OUT`.

### Utils

Набор готовых функций: `ISBON`/`DISBON` (проверка бита), `SETB`/`DSETB`, `RSTB`/`DRSTB`, `SRB`/`DSRB`, регуляторы `HYST`/`HYST_COOL`, счётчики наработки `WORK_LEFT`/`WORK_LEFT_TIME`, `INCN`, `SHIFT`, `L02_SET_IP`, `VALVE_3P`, масштабирование `SCALE`/`DSCALE`/`SCALE_NL`.

### TimeControl

Собственный тикер (аналог `TIME()` из CoDeSys): глобальная переменная `TCO_DINT_50` считает 50-мс интервалы от запуска ПЛК (запас ~3,4 года). Функции преобразования: `TCO_50_TO_SEC`, `TCO_50_TO_100MS`, `TCO_50_TO_MS`, `TCO_50_TO_MIN`, `MIN_TO_TCO_50`, `SEC_TO_TCO_50`, `TCO_50_DIFF`; блоки `TCO_50_BLINK`, `FB_TCO10`; программы тикера `PRG_TCO_TICKER_50` / `PRG_TCO_TICKER_10`.

> **Важно:** перед использованием TimeControl нужно настроить тикер — запустить программу `PRG_TCO_TICKER_50` (или `PRG_TCO_TICKER_10`) в проекте. Это описано в `TimeControl.md`.

### ModbusDriver

Драйвер Modbus RTU для Coolmay FX3G: настройка порта `MB_PORT_SETTINGS`, инициализация slave/master `MB_SLAVE_INIT_PORT2/3`, `MB_MASTER_INIT_PORT2/3`, главный блок обмена `MB_PROCESS_50` (работает по 50-мс тикеру TimeControl). Документация на английском и русском. Требует установки `UtilsV4.sul` и `TimeControlV2.sul` (см. требования в документации).

### Easing

Функции плавного изменения значений от точки `N` к точке `N1` за заданное время. Применяются в позиционировании (разгон/торможение), в управлении насосами фонтанов, в плавном прогреве нагревателей и т. п.

### PumpControl

Управление группой насосов: блок `Cascade_d` поддерживает до 9 насосов, добавляет/убирает насосы по нижнему и верхнему давлению, автоматически ротирует насосы для выравнивания наработки, контролирует температуру и аварии.

### Назначение файлов внутри библиотеки

| Файл / папка | Назначение |
| ------------ | ---------- |
| `<Имя>.sul` | **Готовая библиотека** для установки в GX Works 2. Именно этот файл подключается в рабочий проект. |
| `<Имя>.md` | Документация для конечного пользователя: описание блоков, переменных, примеры. |

| `CHANGELOG.md` | История версий библиотеки. |

> **Важно:** исходные тексты (`POU/`) сейчас есть только у **AlarmManager** — первой библиотеки, переведённой на новые принципы разработки. Остальные библиотеки поставляются как готовый `.sul` + документация.

## Как установить библиотеку в GX Works 2

1. Скопируйте нужный файл `<Имя>.sul` на компьютер, где установлен GX Works 2.
2. В GX Works 2 откройте **Library Manager** (меню *Project → Library* или панель библиотек) и установите файл `.sul`.
3. Библиотека появится в списке библиотек проекта; её функциональные блоки и функции станут доступны в окне *Library*.
4. Если библиотека имеет зависимости (см. таблицу выше), установите их в том же порядке (например, для ModbusDriver сначала Utils и TimeControl).
5. Для TimeControl дополнительно запустите программу тикера `PRG_TCO_TICKER_50` (или `PRG_TCO_TICKER_10`) — см. `TimeControl.md`.

## Новые принципы разработки библиотек

При написании новых библиотек (и при доработке AlarmManager) соблюдаются следующие правила. Они же действуют в проекте-компиляторе.

- **Платформа:** только Mitsubishi FX в GX Works 2 (FX3U, FX3G, FX3S, FX5U); целевой ПЛК — Coolmay FX3G.
- **Язык:** Structured Text (ST); переменные описываются в файлах `.csv` для редактора меток GX Works 2.
- **Префиксы имён POU (только заглавные):**
  - `F_` — функции, `FB_` — функциональные блоки, `ST_` — структуры, `GVL_` — глобальные переменные, `PRG_` — программы.
- **Каждый POU — это пара файлов:** `<Имя>.st` (код) + `<Имя>.csv` (метки). Менять один файл без другого нельзя.
- **Комментарии:** только `(* ... *)`. Строчные `//` и фигурные `{ }` комментарии в GX Works 2 не поддерживаются.
- **Файлы `.csv`** кодируются в **UTF-16LE** (формат GX Works 2).
- **Экземпляры FB** объявляются в стиле CamelCase с префиксом `fb` (например, `fbAMInit : FB_AM_INIT`).
- **Константы** — префикс `c_` (`c_AM_ERROR`), **глобальные переменные** — префикс `g_` (`g_xSystemReady`).
- **Структура проекта из трёх программ:** `PRG_INIT` (разовый запуск, выполняется по импульсу `M8002`), `PRG_MAIN` (бизнес-логика), `PRG_PROCESS` (диагностика, аварии, передача данных). Флаг `M8002` задаётся в настройках задачи программы, а не в коде.
- **Хранилище данных** объявляет приложение (модель пользовательского хранилища): например, AlarmManager использует глобальные массивы `AM_ALARMS` / `AM_EVENTS` и константы `c_AM_ALARMS_NUM` / `c_AM_EVENTS_NUM`, объявленные в проекте.

## Проект-компилятор `compiler.gxw`

`compiler.gxw` — это **единый проект GX Works 2 для сборки и проверки библиотек**. В него подключены все библиотеки (как компоненты `.col`), чтобы:

- компилировать их вместе и сразу видеть ошибки;
- запускать **тестовые программы** и проверять работу библиотек на практике.

### Что подключено в проект

| Компонент | Что это |
| --------- | ------- |
| `AlarmManger` | Библиотека **AlarmManager** (так она называется внутри GX Works 2 — историческое имя хранилища). |
| `TimeControl` | Библиотека **TimeControl**. |
| `UtilsV5` | Библиотека **Utils** (версия 5). |

### Тестовые программы проекта

| Программа | Что проверяет |
| --------- | ------------- |
| `PRG_AM_TEST` | Дымовой тест AlarmManager: регистрирует 3 аварии и 4 события, прогоняет все блоки библиотеки (init, set, orison, reset, has-alarms, is-block, buzzer, pack, events), упаковывает состояния в `R6000` / `D6000` / `M6000` / `D6100` / `M6100…`. |
| `PRG_TCO_TICKER_50` | Тикер TimeControl с шагом 50 мс. |
| `PRG_TCO_TICKER_10` | Тикер TimeControl с шагом 10 мс. |
| `PRG_TEST_TCO_50` | Тест функций TimeControl. |

Исходные тексты тестов лежат в репозитории рядом с библиотеками (например, `libraries/AlarmManager/POU/PRG_AM_TEST.st` / `.csv`).

### Как пользоваться

1. Откройте `compiler.gxw` в GX Works 2.
2. Выполните компиляцию проекта — проверьте, что в окне *Output* нет ошибок.
3. Запустите нужную тестовую программу (переведите проект в режим RUN или используйте симуляцию).
4. Для `PRG_AM_TEST`: принудительно задайте входные условия (`xCondAlarm0…2`, `xCondEvent0…3`, `xReset`, `xEventReset`) и наблюдайте результаты в Device Monitor — так проверяется поведение блоков.
5. Любую найденную ошибку исправляйте в исходных текстах библиотеки (`libraries/AlarmManager/POU/`), затем пересобирайте проект.

### Что пока НЕ входит в проект-компилятор

ModbusDriver, Easing и PumpControl подключены как отдельные библиотеки в свои рабочие проекты, но в `compiler.gxw` их компонентов пока нет — их тестовые программы появятся в проекте по мере перевода этих библиотек на новые принципы.

> **Примечание:** внутри GX Works 2 компонент AlarmManager называется **`AlarmManger`** (опечатка в имени хранилища, заложенная исторически). Не путайте: это та же библиотека AlarmManager.

## Служебные файлы репозитория

- `.pi/` — конфигурация агента разработки: системный промпт (`SYSTEM.md`, `APPEND_SYSTEM.md`), навыки (`skills/`), правила защиты (`defender.yaml`). Конечному пользователю не нужны.
- `.vscode/` — настройки VS Code для генерации PDF-документации из `.md` (расширение Markdown PDF).

---

## Как обновляется документация

- `.md` — основной источник документации, пишется вручную.
- `.pdf` — генерируется из `.md` (расширение VS Code Markdown PDF, см. `.vscode/settings.json`).
- `CHANGELOG.md` — ведётся при каждом изменении библиотеки.
